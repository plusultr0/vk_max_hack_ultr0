## Не выполнено и не выдаётся за успешную проверку

В доступной среде нет Docker CLI и PostgreSQL. Установить закреплённые зависимости не удалось: npm registry недоступен по DNS; offline cache не содержит всех нужных пакетов. Попытка `tsc -p tsconfig.backend.json` завершилась ошибками отсутствующих зависимостей/типов и связанными с ними диагностическими сообщениями.

Поэтому НЕ подтверждены:
- полный workspace typecheck, Vitest и Vite production build;
- выполнение новой SQL-миграции 013 на реальном PostgreSQL;
- PostgreSQL integration suites, включая `journey.integration.ts`;
- настоящий React browser regression из `tests/browser/regression.py`;
- рабочий цикл на сервере пользователя, MAX, GigaChat и отправка уведомлений.

Chromium CSS/layout НЕ является React E2E. Написанные PostgreSQL и browser тесты не считаются пройденными только потому, что их исходники существуют.

## Подготовленные воспроизводимые регрессии

`packages/db/src/journey.integration.ts` создаёт случайную изолированную схему и проверяет:
- 5 обязательных ответов без выдуманных необязательных значений;
- одну отметку карточка/бот/checklist, обе стороны обновления;
- повтор requestId после более нового действия без повторного применения старой отметки;
- запрет чужих и устаревших изменений;
- независимость настоящих документов/настроек;
- перенос прежней checklist-отметки только при совпадающем основании, один раз;
- приоритет более новой отметки action/bot и сохранность immutable history;
- ручной повтор упавшего пересчёта, пропуск занятой worker-ом job-строки без взаимной блокировки;
- before/after на границе страницы истории и audit больше 100 событий без дублей.

`tests/browser/regression.py` запускается против настоящего Vite/React с перехваченным синтетическим API. На 320/375/768/1440 px проверяет ответы и повтор после ошибки, неизменность requestId, редактирование, денежный ввод, общие отметки, возврат в приложение, новую карточку из ленты, источники, ошибку пересчёта. Дополнительные сценарии: onboarding, необязательные сведения, сохранность ввода, ошибка подтверждения после успешного PUT, сброс фильтра, before/after и пагинация.

`compose.test.yaml` использует отдельный `Dockerfile.acceptance` с Chromium и Python и запускает обе группы после основных тестов. Production `.env` исключён из build context, рабочие ключи не передаются, БД находится в tmpfs отдельного Compose-проекта.

## Проверка на стенде после установки зависимостей

```bash
docker compose --env-file .env.test.example -p max-regcontrol-tests -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
docker compose --env-file .env.test.example -p max-regcontrol-tests -f compose.test.yaml down
```

Это отдельная тестовая БД. Нельзя направлять integration tests на рабочую базу.

После развёртывания приложения отдельно проверить внутри MAX: бот → Mini App, отметка через бота → возврат без перезагрузки, карточка → документы → обратная отметка, новая публикация → уточняющий вопрос → уведомление. Реальные внешние вызовы не заменяются синтетическим browser API.
