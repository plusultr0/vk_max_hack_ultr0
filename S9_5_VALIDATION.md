## Сценарии нового блока

- Двойное применение миграций.
- Одновременное создание review: один успех, один конфликт.
- Одновременное сохранение от одной базовой ревизии: один успех, один конфликт.
- Чтение старых ревизий; запрет UPDATE/DELETE ревизий и возврата указателя назад.
- Неизменность исходного извлечения после правок.
- Откат ревизии и указателя при искусственном сбое записи аудита.
- Отказ перевода неполного документа в ready, без появления новой ревизии.
- Сохранение проверенного синтетического пакета из трёх правил.
- Привязка preview к revision + contentHash; различие upcoming/active/ended.
- Блокировка legacy publish для candidate с новым review.
- Защита терминальных состояний и отказ review для legacy-candidate без снимка.
- HTTP 403 для всех новых маршрутов без admin-токена; 400/409/422 для неправильного формата, конфликтов и неготовности.
- Клиент не может подставить свою идентичность автора в POST создания.
- После всех операций review и preview: ноль опубликованных правил, assessments и уведомлений в тестовой схеме.

Unit-проверки дополнительно покрывают потерю исходных элементов, перестановку стабильных ID, исключение с причиной, недопустимые типы и enum, пороги ниже/равно/выше, unknown и false, вложенные AND/OR/NOT, ссылки и даты, область торговой точки, относительные сроки, канонический хеш при порядке ключей JSONB и ограничение глубины ввода.

## Что эти проверки не утверждают

- Юридическая проверка кандидата ЦБ не завершена. Реальный сохранённый JSON используется только как регрессионный пример; AI-ошибки не объявлены правильными.
- UI проверки, публикация пакета, outbox и исправления боевого выбора версий ещё не входят в этот блок.
- MAX live не проверен; значения параметров бота в предоставленном `.env` отсутствуют.
- Новые live-запросы GigaChat и официальных источников для этого блока не требовались.
