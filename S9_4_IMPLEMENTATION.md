# S9.4 — источник, сегменты, этапы и проверка структуры

Реализован первый блок плана: воспроизводимые зависимости, проверка контейнерного запуска, source-segment extraction и структура сроков/этапов. Полноценный редактор human review и надёжная очередь publish/reassessment — следующие блоки.

## Контракт extraction

Модель возвращает `title`, `summary`, `phases`, `dateNotes`, `uncertaintyNotes`. Этап содержит условия, исключения, действия, даты и ссылки `sourceSegmentIndexes`. Модель не возвращает `evidence`, `quote` или `sourceSnapshot`: неизвестные поля отклоняются.

Сервер добавляет:

- `schemaVersion = reg-extract-v4-source-segments`;
- `sourceSnapshot`: текст, SHA-256, название, URL, происхождение, время фиксации, известное время получения источника и точные сегменты;
- `evidence`: `{ index, sourceSegmentIndex, quote }`, где quote берётся из сегмента без нормализации пробелов.

Индекс evidence равен индексу source segment. Поля черновика ссылаются непосредственно на sourceSegmentIndexes, а не на отдельный индекс, придуманный моделью. Смещения `start/end` измеряются в UTF-16 code units, как JavaScript String.slice. Версия сегментации `exact-chunks-v1` — части до 1000 символов с предпочтением границ предложений/строк и без разрыва surrogate pair. Соединение сегментов восстанавливает входной текст полностью.

Снимок фиксирует текст, поданный на extraction. Для HTML это читаемый текст после существующего HTML-парсера, а не оригинальные байты страницы. Ручной текст сохраняется с origin=request; он не становится автоматически проверенным официальным текстом из-за указанного URL. Источники длиннее 120000 UTF-16 code units теперь отклоняются, а не обрезаются молча.

## Сроки, даты и условия

- Дата этапа: `{ date: "YYYY-MM-DD" | null, sourceSegmentIndexes: [...] }`.
- Срок — строго один из четырёх вариантов: `{kind:"fixed",date,sourceSegmentIndexes}`, `{kind:"relative",description,sourceSegmentIndexes}`, `{kind:"phase_start"}` или `{kind:"unknown"}`. Лишние поля запрещены самим JSON-контрактом.
- Fixed требует существующую календарную дату и ссылки на её явное упоминание. Relative требует дословное описание относительного срока и ссылки. Unknown не содержит дополнительных полей.
- Phase_start — срок подготовки к началу этапа, а не отдельная правовая дата. У него нет собственных date/description/ссылок; `resolveDraftDeadline()` возвращает дату и доказательства из проверенного validFrom с origin=derived-from-phase. Связь действия с этапом требует подтверждения человеком.
- Поддерживается распознавание полных дат ISO, ДД.ММ.ГГГГ и русских дат вида «1 сентября 2026». Год без дня и месяца не преобразуется в выдуманную полную дату.
- Поля условий сверяются с CompanyProfileSchema; значения и операторы проверяются по типам, включая enum и массивы. Отсутствующий в профиле признак сохраняется как null/other/null с объяснением для проверяющего.
- Разные этапы сохраняются в phases, будущие этапы не должны скрываться только в заметках. Непредставленная распознанная дата вызывает repair; даты публикаций и других контекстов допускаются в структурированных dateNotes с объяснением.

Сервер даёт модели каталог типов/допустимых значений и подсказки сегментов с датами. Ошибки JSON, Zod-схемы, ссылок и проверок направляются в одну repair-попытку. Повторный провал завершает extraction ошибкой без candidate. HTTP/TLS/OAuth/timeout не маскируются как ошибки схемы.

Эти проверки гарантируют происхождение цитат и ряд структурных свойств, но не юридическую правильность интерпретации. Они не доказывают полноту всех исключений, правильность порога или логических связей условий. Контекст даты и правильность отнесения к dateNotes требуют проверки человеком. Условия черновика ещё не являются исполняемым DSL.

## Хранение и совместимость

Миграция `007_source_snapshots.sql` добавляет таблицу source_snapshots и nullable source_snapshot_id у candidates. Снимок и candidate записываются в одной транзакции. Перед сохранением повторно проверяются hash, сегменты, схема, ссылки и серверные цитаты.

Триггеры запрещают UPDATE/DELETE снимка и изменение исходных draft/evidence/provenance у candidate. Метаданные review могут обновляться. Обновление staging-документа не затрагивает ранее сохранённые снимки. Полный снимок доступен через защищённый `GET /admin/candidates/:id`; список candidates не передаёт весь текст и берёт название/URL из снимка.

Прежние candidates остаются читаемыми с source_snapshot=null. Их публикация запрещена с `LEGACY_CANDIDATE_REEXTRACTION_REQUIRED`: для старых цитат нельзя задним числом доказать принадлежность точному снимку. Повторите extraction.

Публикация кандидата с несколькими этапами или без этапов через прежний endpoint одного правила блокируется. Это предотвращает молчаливую потерю этапов до реализации отдельного review/publish workflow. Один этап можно передать в существующий ручной publish API после проверки. Известный разрыв между COMMIT публикации и пересчётом компаний остаётся задачей следующего блока.

## Запуск и проверки (PowerShell, из папки проекта)

Существующую конфигурацию `.env` сохраните. Для чистого запуска подготовьте `.env` по `.env.example`.

```powershell
docker compose up -d --build
curl.exe http://localhost:3000/health
curl.exe http://localhost:3001/health
docker compose run --rm --no-deps worker npm run check
docker compose run --rm --no-deps -e ALLOW_INTEGRATION_TESTS=true worker npm run test:integration
```

Интеграционный тест создаёт собственную случайную схему в указанной БД, дважды применяет миграции, проверяет хранение, неизменность, rollback и чтение legacy, затем удаляет только свою схему. Данные приложения не удаляются.

Короткий smoke с текущим LLM_PROVIDER:

```powershell
docker compose run --rm --no-deps worker npm run llm:smoke
```

Проверка полной страницы ЦБ через выбранный реальный провайдер (сохраняет pending candidate, не публикует):

```powershell
docker compose run --rm --no-deps -e LLM_TIMEOUT_MS=120000 worker npm run llm:source-check
```

На полной странице 45 секунд оказалось недостаточно. Лимит 120 секунд в этой команде применяется только к процессу проверки. Если он нужен для extraction через API, задайте `LLM_TIMEOUT_MS=120000` в своей конфигурации и пересоздайте сервисы. При этом одна repair-попытка может потребовать второго запроса такой же длительности.

`llm:source-check` проверяет наличие дат этапов 2026/2027/2028 для текущего демонстрационного сценария ЦБ. Изменение официальной страницы может потребовать пересмотра этих ожиданий. Результат остаётся черновиком для человека.

Для остановки сохраняйте том:

```powershell
docker compose down
```

Не используйте `down -v` для обычной остановки: это удаляет БД.
