# Проверка версии 0.9.18

Дата исполнения: 28.09.2026.

## Итог

0.9.18 продолжает фактический source-state 0.9.17 без пересборки проекта с нуля. Проект не создавался заново, модель данных и seed-37 не переписывались. Рабочий `.env` не заменялся и после правок имеет тот же SHA-256:

`0ad24632befd02d343fa3a9b074c18395371318396dec406b5ac2ed6fc2c9e94`

Цель версии — убрать из каждой карточки требования дублирующий блок «Ваши ответы, которые повлияли на результат» вместе со списком введённых значений, не меняя расчёт требований и сохранённые ответы.

## Успешно выполнено в этой среде

- `node scripts/test-core-offline.mjs`: **189/189 passed, 0 failed, 0 skipped**;
- `node scripts/test-chatbot-offline.mjs`: **9/9 chatbot routing/copy checks**;
- `node scripts/check-syntax.mjs`: **102 TS/TSX файла, 0 syntax errors**;
- `python3 tests/layout/check_layout.py --chromium /usr/bin/chromium --output test-results/layout-0.9.18`: **80/80 CSS/layout cases**;
- layout widths: **320, 375, 768, 1024, 1440 px**;
- `.env`: **без изменений**.

CSS/layout gate использует production `styles.css` и HTML fixtures. Он проверяет overflow, навигацию, touch targets, повторяющиеся края/ширины и интервалы, но не является React E2E и не запускает backend.

## Регрессия последнего пользовательского сценария

В offline core добавлена отдельная проверка НДС:

- УСН, нет совмещения режимов, доход за 2025 год 350 млн ₽, регистрация 09.09.2024 → правило начала НДС с 01.01.2026 **применяется**;
- те же данные, но регистрация 09.09.2026 → это же правило **не применяется**.

Evaluator не менялся ради UX-запроса: найденное пользователем различие связано с датой регистрации. В карточке действие больше не говорит «покажите бухгалтеру дату из этой карточки»: для стартового правила прямо указано **1 января 2026 года**, а для правила превышения порога в течение 2026 года UI подставляет рассчитанную `effectiveFrom`.

## UX 0.9.18, проверенный статически

- из всех карточек требования удалён блок «Ваши ответы, которые повлияли на результат» и таблица использованных значений;
- «Исправить ответы», уточняющие вопросы, действия и официальные источники сохранены;
- удалены eyebrow `МОЙ БИЗНЕС` и `ПРОВЕРКА БИЗНЕСА` в пользовательских экранах;
- onboarding содержит только короткое описание и 8 вопросов одной последовательностью;
- удалены группы «О бизнесе», «Продажи и оплата», «Данные покупателей» и старый progress track;
- вокруг пояснения «Эти ответы нужны…» остаются только верхний и нижний разделители;
- география поддерживает presets «По всей России» / «Россия и СНГ» плюс ручной охват без миграции существующего `region`;
- текущий seed не содержит ни одного правила, которое зависит от `region`, поэтому evaluator не получил искусственную региональную ветку;
- объект УСН «Доходы» / «Доходы минус расходы» не вынесен в отдельное поле: текущие правила проверяют сам режим УСН и другие факты, но не объект УСН;
- основной пользовательский раздел называется «Требования», список — «Требования», фильтр — «Все требования»;
- удалён большой scope-disclaimer с главного списка;
- dynamic questions используют `Вопрос 1 из 3` без zero-padding и без лишнего текста под заголовком;
- поля денежных сумм в рублях группируют цифры пробелами при вводе, а parser по-прежнему отправляет число;
- при `not_applicable` блок причины показывает итоговую human-facing формулировку, а не текст о недостающих полях;
- разделители рисуются нижней границей предыдущего вопроса с отдельным вертикальным отступом, поэтому линия не пересекает `legend`.

## Что не заявляется как пройденное

Docker CLI в среде отсутствует. Попытка дополнительно выполнить свежий `npm ci --ignore-scripts` не завершилась в доступное время; процесс был остановлен, частичный `node_modules` удалён. Поэтому здесь **не заявляются**:

- full workspace TypeScript typecheck;
- workspace Vitest suite с реальными зависимостями;
- Vite production build;
- PostgreSQL integration;
- настоящий React browser E2E;
- live MAX/Yandex Cloud acceptance 0.9.18.

Последняя подтверждённая live-версия из handoff — 0.9.14. 0.9.15 (interactive bot), 0.9.16 (feed completeness), 0.9.17 (UX follow-up) и 0.9.18 (удаление дублирующих ответов) нужно развернуть вместе на существующем стенде.

## Required deployment acceptance

На существующем сервере **сохранить production `.env`**, заменить исходники и выполнить:

```bash
docker compose up -d --build api bot worker web
docker compose ps -a
curl -fsS http://127.0.0.1:3000/health; echo
curl -fsS http://127.0.0.1:3001/health; echo
docker compose exec bot npm run bot:subscribe
```

Не использовать `docker compose down -v` для рабочего стенда.

После развёртывания пройти `BOT_SCENARIOS_0.9.15.md` и отдельно проверить Mini App 0.9.18:

1. новый профиль на 320/375 px;
2. presets географии и существующее старое значение региона;
3. сохранение профиля → раздел «Требования»;
4. карточку с несколькими dynamic facts;
5. ввод `35000000` → визуально `35 000 000` → корректный числовой ответ backend;
6. НДС start-2026 для регистрации до 2026 года;
7. НДС during-2026 с рассчитанной датой следующего месяца;
8. `not_applicable`, `needs_info`, `action_required`, completed и history.

## Сохранённые продуктовые инварианты

- `unknown != false`;
- `applies != violation`;
- source/evidence остаются server-owned и grounded;
- история completed/stale actions не уничтожается новой версией правила;
- 37 seed requirements — пилотный каталог требований, а не заявление о полноте законодательства.
