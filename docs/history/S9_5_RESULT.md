# S9.5A/B — результат разработки

17.09.2026. Версия проекта: **0.9.5**. Выполнен серверный блок проверки нормативного черновика человеком. Локальный API обновлён; интерфейс mini-app пока прежний.

## Изменения и причины

| Изменение | Для чего |
|---|---|
| Отдельные неизменяемые ревизии review | Правки человека сохраняются с причиной и временем, исходный AI-черновик не перезаписывается |
| Стабильные идентификаторы этапов и элементов | Можно переставлять элементы, но нельзя незаметно потерять условие, исключение или действие |
| Явные решения include/exclude/unresolved | Непроверенное содержание блокирует готовность; исключение требует объяснения |
| Компилятор проверенной структуры в DSL | Проверяет типы, AND/OR/NOT, источники, даты, вопросы и область применения |
| Проверка компании и торговой точки | Исключение для одной точки не превращается в освобождение всей компании |
| API сохранения и истории | Каждое сохранение создаёт новую ревизию; одновременные правки дают конфликт вместо потери данных |
| Предпросмотр по revision + contentHash | Расчёт связан с конкретной ревизией и не создаёт опубликованных правил, действий или уведомлений |
| Защита терминальных состояний candidate | Отклонённый/утверждённый кандидат нельзя вернуть в другую ветку прежним вызовом |

Текущая авторизация использует общий admin-токен: в истории честно записывается `admin-token`, а не выдуманная личность сотрудника. Персональная авторизация редактора ещё впереди.

## Что дальше

Следующий блок — минимальный административный UI: источник рядом с полями, переход к цитатам, список замечаний, решения, история ревизий и предпросмотр.

Затем — публикация целого проверенного пакета, outbox и восстановление пересчёта, выбор действующих версий, сохранение выполненных действий и актуальные напоминания. Новый review пока намеренно не публикуется через старый одноэтапный endpoint.

Текущий предпросмотр поддерживает начало включительно и конец исключительно: `[validFrom, validTo)`. Иные способы задания конца, относительные сроки и несколько торговых точек в боевом профиле требуют дальнейшего расширения. Полнота юридического смысла проверяется человеком; успешная компиляция её не доказывает.

В предоставленном `.env` отсутствуют MAX_BOT_TOKEN, MAX_BOT_USERNAME и MAX_WEBHOOK_SECRET; live-сценарий MAX пока не проверен. `.env` не менялся, новых запросов к GigaChat не выполнялось.
