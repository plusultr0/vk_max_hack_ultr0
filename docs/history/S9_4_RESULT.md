## Как обновить существующую установку

Сохраните свою `.env` и PostgreSQL volume. Распакуйте архив в существующую папку проекта с заменой исходников. Архив не содержит `.env` и не заменит её.

Из той же папки и с тем же Compose project name, который использовался раньше:

```powershell
docker compose up -d --build
docker compose run --rm --no-deps worker npm run check
docker compose run --rm --no-deps -e ALLOW_INTEGRATION_TESTS=true worker npm run test:integration
```

Если раньше использовался `docker compose -p <имя>`, сохраните этот параметр во всех командах: смена project name создаёт другой том вместо подключения прежней БД.

Повторить live extraction ЦБ (сохраняет только черновик):

```powershell
docker compose run --rm --no-deps -e LLM_TIMEOUT_MS=120000 worker npm run llm:source-check
```

Если длинные extraction нужны через API, можно установить `LLM_TIMEOUT_MS=120000` в своей `.env` и пересоздать сервисы. Причина — полный многоэтапный документ не уложился в прежние 45 секунд. При repair возможен второй запрос такой же длительности.

Для новой установки сначала подготовьте `.env` по примеру либо перенесите свою существующую конфигурацию. Полный архив не включает БД: существующие candidates не появятся в новой базе автоматически.
